# تحصين أمان المنصة

## النطاق

تغطي هذه المرحلة المصادقة متعددة العوامل، دورة حياة رمز التهيئة، تحديد المعدل الموزع، حماية المرفقات، توثيق Webhooks، رؤوس الاستجابة، وسلامة سجلات التدقيق. لا تنشئ هذه المرحلة سياسات PostgreSQL RLS ولا تعيد اختبارات IDOR المنفذة في المرحلة السابقة.

## نموذج التهديد

الضوابط تستهدف بصورة مباشرة:

- سرقة جلسة مالك أو مدير ثم استخدامها لتغيير مزودات الذكاء الاصطناعي أو الأعضاء أو التكاملات أو تشغيل أدوات عالية الأثر.
- إعادة استخدام رمز تهيئة قديم أو تسريبه بعد إنشاء النظام.
- تجاوز حدود الطلبات عند تشغيل عدة نسخ من التطبيق.
- كشف ملف خاص بواسطة رابط دائم أو قبل فحصه.
- إرسال Telegram Webhook مزيف إلى مسار معروف.
- حذف أو تعديل آثار عملية إدارية بعد وقوعها.

## القرارات الهندسية

### MFA للمالكين والمديرين

يُطبق TOTP وفق RFC 6238 باستخدام SHA-1، ست خانات، وفترة 30 ثانية. السر مشفر بواسطة طبقة التشفير الحالية مع سياق مستقل لكل مستخدم. يحفظ النظام عداد آخر رمز مستخدم لمنع replay داخل نافذة الوقت.

رموز الاسترداد:

- تولد مرة واحدة عند إكمال التسجيل.
- تخزن مشفرة للوفاء بمتطلب الاسترداد الآمن.
- تخزن أيضًا بصمة SHA-256 للبحث دون فك كل السجلات.
- تستخدم مرة واحدة ثم يضبط `used_at` ذريًا.

التحقق مرتبط بالجلسة، وصلاحيته 12 ساعة. العمليات الحساسة للأدوار `owner` و`admin` تمر عبر `requireSession(permission)` الذي يفرض RBAC ثم MFA. القراءات غير الحساسة وباقي الأدوار لا تتغير.

### رمز التهيئة

`BOOTSTRAP_ADMIN_TOKEN` لم يعد مفتاحًا ثابتًا طويل العمر. يلزم:

- طول لا يقل عن 32 حرفًا.
- `BOOTSTRAP_ADMIN_TOKEN_EXPIRES_AT` بصيغة ISO-8601.
- استخدام واحد فقط داخل نفس transaction التي تنشئ المورد الأول.
- تسجيل request ID وبصمة عنوان المصدر دون حفظ العنوان الخام.
- منع التدوير الصامت بعد إنشاء سجل التحكم.
- تعطيل نهائي عبر `npm run bootstrap:disable`.

بعد التهيئة يجب حذف متغير الرمز وكلمة المرور الأولية من منصة الاستضافة، ثم تشغيل أمر التعطيل النهائي.

### Rate Limiting موزع

الحدود تستخدم Upstash Redis REST وLua `EVAL` لزيادة عداد النافذة وتثبيت TTL ذريًا. لا تستخدم جداول PostgreSQL في مسار تحديد المعدل.

في الإنتاج:

- غياب Redis يؤدي إلى fail closed برمز 503.
- يطبق حد عام على `/api/*` باستثناء health/readiness.
- توجد حدود إضافية لتسجيل الدخول، تحقق MFA، رفع الملفات، Webhooks، الدردشة، وتشغيل الوكلاء.

الذاكرة المحلية fallback متاحة فقط خارج الإنتاج لاختبارات الوحدة والتطوير المحلي.

### Webhooks

Telegram يتحقق من `X-Telegram-Bot-Api-Secret-Token` بمقارنة ثابتة الزمن مع البصمة المخزنة، ويرفض الطلب قبل استدعاء `request.json()`. يسجل الرفض كحدث أمني ويطبق حدًا موزعًا بعد نجاح التحقق.

WhatsApp يحتفظ بالتحقق من توقيع Meta قبل JSON والمعالجة، ويستفيد أيضًا من الحد العام وحد الهاتف المخصص.

### رؤوس الأمان

`src/proxy.ts` يضيف:

- Content-Security-Policy مع nonce و`frame-ancestors 'none'`.
- Strict-Transport-Security في الإنتاج.
- X-Frame-Options: DENY.
- X-Content-Type-Options: nosniff.
- Referrer-Policy.
- Permissions-Policy.
- COOP وCORP وOrigin-Agent-Cluster.
- تعطيل cache لمسارات المصادقة ولوحة التحكم وواجهات API.

### سجلات التدقيق

قاعدة البيانات ترفض `UPDATE` و`DELETE` و`TRUNCATE` على `audit_logs` عبر triggers. التطبيق يضيف أحداثًا لعمليات MFA، استخدام رمز التهيئة، فحص المرفقات، محاولات الوصول المرفوضة، وعمليات الإدارة الحساسة الموجودة أصلًا.

هذا يمنع التعديل العرضي أو عبر التطبيق. مالك قاعدة البيانات أو superuser يستطيع إزالة trigger؛ لذلك يوصى بتقييد صلاحيات التطبيق ومراقبة تغييرات DDL ونسخ السجلات إلى وجهة خارجية غير قابلة للتعديل.

## متغيرات الإنتاج الإلزامية

```dotenv
UPSTASH_REDIS_REST_URL=https://...
UPSTASH_REDIS_REST_TOKEN=...
ATTACHMENT_SIGNING_SECRET=<32+ random characters>
ATTACHMENT_URL_TTL_SECONDS=60
ANTIVIRUS_REQUIRED=true
CLAMAV_HOST=clamav.internal
CLAMAV_PORT=3310
CLAMAV_TIMEOUT_MS=30000
```

عند الحاجة إلى التهيئة المؤقتة فقط:

```dotenv
BOOTSTRAP_ADMIN_TOKEN=<32+ random characters>
BOOTSTRAP_ADMIN_TOKEN_EXPIRES_AT=2026-08-05T12:00:00Z
```

## إجراءات النشر

1. طبق migrations في بيئة اختبار نظيفة.
2. وفر Redis وClamAV قبل رفع web وworker.
3. تأكد أن web وworker يستخدمان مفتاح التشفير نفسه.
4. استخدم bucket خاصًا؛ لا تضبط `R2_PUBLIC_BASE_URL`.
5. نفذ smoke test لتسجيل الدخول وMFA ورفع ملف نظيف وملف EICAR في بيئة معزولة.
6. تحقق من رفض Telegram secret غير الصحيح قبل تسليم JSON.
7. بعد أول تهيئة، نفذ `npm run bootstrap:disable` واحذف الأسرار المؤقتة.

## المخاطر المتبقية

- TOTP مقاوم لسرقة كلمة المرور لكنه ليس مقاومًا للتصيد مثل WebAuthn؛ يوصى بإضافة passkeys لاحقًا.
- ClamAV يعتمد على حداثة قاعدة التواقيع وعلى توفر الخدمة؛ يجب مراقبة تحديثاتها وزمن الاستجابة.
- الروابط الموقعة bearer URLs؛ من يحصل عليها يستطيع استخدامها حتى انتهاء الدقيقة الافتراضية. لا تُسجل query strings في logs.
- trigger سلامة audit ليس بديلًا عن WORM خارجي أو صلاحيات قاعدة بيانات منفصلة.
- Upstash REST اعتماد خارجي؛ يجب ضبط تنبيه availability وquota واختيار منطقة قريبة من التطبيق.
