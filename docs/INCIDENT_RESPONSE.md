# الاستجابة للحوادث

## التسلسل

1. أعلن قائد حادثة وسجل وقت البداية والأنظمة المتأثرة دون نسخ بيانات حساسة.
2. احتوِ الضرر عبر feature flag أو تعطيل credential/integration أو وقف Worker، لا عبر خفض المصادقة.
3. احفظ logs المنقحة وrequest/run IDs ونسخة إعدادات غير سرية.
4. صحح السبب، اختبر في بيئة معزولة، انشر تدريجيًا، ثم اكتب postmortem بلا لوم.

## مفتاح مزود مسرب

- أبطله لدى المزود أولًا، عطّل السجل محليًا، راجع audit وusage، أدخل مفتاحًا جديدًا عبر مسار التحقق، ولا تضعه في ticket أو chat.

## اشتباه بمفتاح تشفير

- اعتبر كل ciphertext ضمن النطاق معرضًا، قيّد الوصول، نفذ runbook التدوير بمفتاح جديد، ودوّر أيضًا provider/OAuth tokens بحسب المخاطر. لا تحذف المفتاح القديم قبل تحقق إعادة التشفير، واحفظه في secret manager مقيد خلال rollback فقط.

## تجاوز عزل أو حساب مخترق

- أبطل جلسات الويب والهاتف ومفاتيح API، جمّد عمليات الكتابة المتأثرة، حدد المؤسسات والموارد عبر audit IDs، ولا تستخرج محتوى محادثات إلا بصلاحية حادثة معتمدة.

## فشل migration أو ارتفاع أخطاء

- أوقف rollout، قارن request IDs وerror codes، تحقق من readiness/pool/queue، ثم rollback للكود مع إبقاء migrations additive. الاستعادة من backup قرار قائد الحادثة بعد إثبات فساد البيانات.
