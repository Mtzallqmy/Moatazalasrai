# أمان المرفقات

## الحالة الافتراضية

كل مرفق خاص افتراضيًا. لا يوجد public bucket ولا رابط دائم ولا مسار يخدم الملف مباشرة بعد الرفع.

دورة الحالة:

1. `quarantined`: خُزن الملف لكن لا يمكن تنزيله أو استخدامه في محادثة أو قاعدة معرفة.
2. العامل ينفذ مهمة `attachment-scan` ويقرأ المحتوى من التخزين الخاص.
3. ClamAV يفحص stream كاملًا قبل الاستخراج أو المعالجة.
4. `ready`: الفحص نظيف، ثم ينفذ parser ويصبح الملف قابلًا للاستخدام.
5. `failed`: تعذر الفحص أو التحليل؛ يبقى غير متاح.
6. `quarantined` مع `MALWARE_DETECTED`: اكتُشف ملف ضار ويبقى محجورًا.

## التخزين

- `database`: توافق قديم؛ المحتوى يبقى bytea خاصًا.
- `local`: ملفات بصلاحية `0600` داخل مجلد `0700`، مناسب لتطوير أو نسخة واحدة فقط.
- `r2`: bucket خاص، بلا ACL عام، مع `Cache-Control: private, no-store`.

يمنع التحقق التشغيلي ضبط `R2_PUBLIC_BASE_URL` في الإنتاج. يجب تعطيل public access على مستوى bucket أيضًا.

## التسليم

بعد نجاح authorization لا يعيد مسار الملفات المحتوى مباشرة. يصدر redirect مؤقتًا إلى `/api/attachments/download?token=...`.

التوكن:

- HMAC-SHA256 باستخدام `ATTACHMENT_SIGNING_SECRET`.
- يربط `attachmentId` و`organizationId` ووقت الانتهاء ونمط العرض.
- المدة الافتراضية 60 ثانية والحد الأعلى 300 ثانية.
- التلاعب أو تجاوز المدة أو انتهاء الصلاحية يرفض.
- download endpoint يعيد فحص وجود السجل والمؤسسة وحالة `ready`.

الروابط bearer URLs؛ لا تضعها في analytics أو Referer أو سجلات reverse proxy. يضيف المسار `Referrer-Policy: no-referrer` و`Cache-Control: no-store`.

## ClamAV

متغيرات العامل:

```dotenv
ANTIVIRUS_REQUIRED=true
CLAMAV_HOST=clamav.internal
CLAMAV_PORT=3310
CLAMAV_TIMEOUT_MS=30000
```

يتحدث العامل ببروتوكول `INSTREAM` ولا يرسل الملف إلى خدمة عامة. يجب:

- تحديث signatures بصورة دورية ومراقبة عمر قاعدة التواقيع.
- عزل شبكة ClamAV بحيث يقبل اتصالات العامل فقط.
- تحديد CPU والذاكرة والحجم الأقصى للملفات والأرشيفات.
- مراقبة timeouts وqueue depth.

في الإنتاج، غياب ClamAV أو فشل الاتصال يمنع الملف من الانتقال إلى `ready`. في التطوير يمكن ضبط `ANTIVIRUS_REQUIRED=false`، وعندها يسجل الفحص `skipped` قبل parser.

## الملفات المضغوطة

فحص التوقيع لا يلغي مخاطر archive bombs. parser الحالي يطبق حدود الحجم وعدد العناصر؛ يجب إبقاء الحدود منخفضة، وعدم فك أرشيفات داخل مسار web، ومراقبة الاستهلاك في العامل.

## الاستجابة للحوادث

عند `MALWARE_DETECTED`:

1. لا تحاول فتح الملف من واجهة الإدارة.
2. احتفظ ببصمة SHA-256 واسم توقيع ClamAV في سجل الحادث.
3. احظر البصمة في upload policy إذا تكرر الهجوم.
4. راجع المستخدم والمصدر والمحادثة المرتبطة.
5. احذف object بعد انتهاء متطلبات التحقيق والاحتفاظ.
6. لا تغير الحالة إلى `ready` يدويًا.

## اختبارات ما قبل النشر

- ملف نصي وصورة نظيفان ينتقلان من `quarantined` إلى `ready`.
- ملف EICAR في بيئة اختبار معزولة يبقى محجورًا.
- تنزيل ملف قبل الفحص يعيد `ATTACHMENT_QUARANTINED`.
- رابط صالح يعمل مرة خلال مدته، والرابط المنتهي يعيد `ATTACHMENT_LINK_EXPIRED`.
- تغيير byte واحد في التوكن يؤدي إلى `ATTACHMENT_LINK_INVALID`.
- مسار مؤسسة أخرى لا يصدر الرابط أصلًا، والتوكن نفسه يربط المؤسسة داخل التوقيع.
- لا يظهر object key أو R2 credential في استجابة API.
