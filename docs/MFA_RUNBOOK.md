# دليل تشغيل TOTP MFA

## السياسة

التحقق الثنائي إلزامي لكل مستخدم يحمل دور `owner` أو `admin` عند تنفيذ عملية حساسة. لا يكفي امتلاك جلسة صحيحة أو صلاحية RBAC؛ يجب أن تكون الجلسة نفسها موثقة بـMFA وغير منتهية.

مدة توثيق الجلسة الحالية 12 ساعة. تغيير المؤسسة لا ينقل توثيقًا بين مستخدمين أو جلسات، وإبطال الجلسة يحذف سجل MFA المرتبط بها بواسطة المفتاح الأجنبي.

## التسجيل

1. يسجل المستخدم الدخول من الويب.
2. يستدعي `POST /api/auth/mfa/enroll`.
3. تعرض الواجهة `otpauthUri` أو السر يدويًا داخل قناة TLS فقط.
4. يدخل المستخدم أول رمز من تطبيق المصادقة عبر `PUT /api/auth/mfa/enroll`.
5. يعرض النظام رموز الاسترداد مرة واحدة، ويطلب حفظها في مدير كلمات مرور.

لا تسجل `secret` أو `otpauthUri` أو رموز الاسترداد في logs أو analytics أو أدوات دعم العملاء.

## التحقق

يستدعي المستخدم `POST /api/auth/mfa/verify` مع:

```json
{ "code": "123456" }
```

أو رمز استرداد. يحدد endpoint حدًا للمحاولات، ويرفض إعادة استخدام TOTP لنفس العداد، ويستهلك رمز الاسترداد ذريًا.

بعد النجاح يمكن للجلسة تنفيذ العمليات الحساسة حتى انتهاء مدة التحقق. يعيد الخادم أحد الرمزين:

- `MFA_ENROLLMENT_REQUIRED`: الحساب الإداري لم يكمل التسجيل.
- `MFA_REQUIRED`: التسجيل موجود لكن الجلسة لم تتحقق أو انتهت صلاحيتها.

## الهاتف

حسابات `owner` و`admin` ترسل `mfaCode` في طلب تسجيل دخول الهاتف. لا يصدر الخادم mobile session إداريًا دون MFA. ترتبط علامة التحقق بمعرف mobile session، وتُفحص قبل API write scopes.

## رموز الاسترداد

- عشرة رموز عند التسجيل.
- كل رمز صالح مرة واحدة.
- القيمة مشفرة، والبصمة تستخدم للعثور الذري على السجل.
- ظهور رمز استرداد مستخدم أو مسرب يتطلب تدوير العامل وإبطال الجلسات.

إعادة إصدار رموز الاسترداد تتم بإعادة التسجيل؛ هذه العملية تستبدل السر والرموز السابقة، لذلك يجب تنفيذها بعد تحقق قوي ودعم تشغيلي موثق.

## استرداد حساب إداري

لا تعطل MFA مباشرة بناءً على طلب بريد أو تذكرة دعم. الإجراء الموصى به:

1. تحقق من هوية الشخص بقناتين مستقلتين.
2. احصل على موافقة مالك آخر إن وجد.
3. أبطل الجلسات النشطة.
4. سجّل تذكرة تغيير وأثرًا إداريًا خارجيًا.
5. أعد تهيئة العامل، ثم اطلب تسجيل TOTP جديد فورًا.

لا يوجد endpoint عام لتعطيل MFA في هذه المرحلة عمدًا. أي إجراء break-glass يجب أن يتم بمهاجرة أو سكربت إداري محدود ومراجع، وليس بتعديل يدوي غير مسجل.

## تدوير مفتاح التشفير

أسرار TOTP ورموز الاسترداد تستخدم `CREDENTIAL_ENCRYPTION_KEY` مع سياقات MFA منفصلة. عند التدوير:

1. أضف المفتاح السابق إلى `CREDENTIAL_ENCRYPTION_PREVIOUS_KEYS`.
2. اضبط مفتاحًا ومعرفًا جديدين على web وworker معًا.
3. أعد تشفير الأسرار باستخدام أداة التدوير المعتمدة.
4. تحقق من تسجيل الدخول وTOTP ورمز استرداد تجريبي.
5. أزل المفتاح السابق فقط بعد اكتمال إعادة التشفير والتحقق والنسخ الاحتياطي.

## المراقبة

نبه على الارتفاع في الأحداث:

- `security.access.denied` بسبب MFA.
- `mfa.verified` باستخدام recovery.
- محاولات `MFA_CODE_INVALID` المتكررة.
- تسجيل إداري من جهاز أو منطقة جديدة.

لا تتضمن أحداث التدقيق الرمز نفسه أو سر TOTP.
